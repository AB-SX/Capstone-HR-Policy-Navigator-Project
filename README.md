Track B — “API-Side” Capstone (no direct model access, ≤8B model behind an endpoint)TitleMulti-Agent Operations Copilot: An Agentic System Built Entirely on a Hosted ≤8B Inference APIScenarioThe team is given only an OpenAI-compatible chat-completions endpoint backed by a single shared ≤8B instruct model, plus an embeddings endpoint. They cannot change weights, inspect logits, or swap in a frontier model. Everything must be won through prompting, retrieval, tool design, orchestration and evaluation. This is deliberately the harder engineering discipline — and closer to what most participants will actually do at work.Suggested domains: procurement and vendor-review assistant, travel-and-expense policy agent, competitive-research analyst, incident postmortem drafter, financial-report question-answering agent, HR policy navigator.What the team must buildI.Task decomposition (Week 1). A written specification of what the copilot does, what it must refuse, and what a correct answer looks like. Plus an evaluation set of 60–100 realistic queries with gold answers, written before any code.II.Prompt engineering baseline (Week 1). Single-agent, single-prompt attempt. Systematic comparison of at least three prompting strategies (structured output with few-shot, chain-of-thought or self-consistency, decomposition prompting). Small models break in specific ways — the team must document how theirs breaks.III.RAG over a real corpus (Week 2). 500–2,000 documents. Required: chunking experiments, hybrid retrieval (BM25 plus dense), a reranker, and citation-grounded answers. Retrieval recall@k must be measured separately from end-to-end answer quality — a key diagnostic when the generator is weak.IV.Agentic layer (Week 3). A multi-agent or tool-using system (LangGraph, CrewAI, AutoGen, or hand-rolled) with at least three tools, an explicit planner→executor→critic loop, persistent state across turns, and error handling for tool failures, malformed JSON, infinite loops and token budget caps.V.Evaluation and observability (Week 3–4). End-to-end accuracy against the Week 1 evaluation set, task completion rate, average tool calls per task, cost and latency per query, and a failure taxonomy separating retrieval miss, reasoning error, tool-call error and hallucination. Tracing via LangSmith, Langfuse or OpenTelemetry.VI.Ship it (Week 4). Streamlit or React front-end, containerised, with rate limiting and caching. Responsible-AI section covering prompt-injection tests against the document corpus, PII handling, refusal behaviour, and a stated human-in-the-loop boundary for consequential actions.Small models fumble tool calls, so constrained decoding, JSON schema validation and retry logic are the core engineering content of this track.
